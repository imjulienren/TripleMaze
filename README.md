# TripleMaze

一款将箭头解谜与同色三消结合的休闲 Puzzle Demo，使用 Unity 2022.3.62f3 开发，包含首页、游戏页、结果页和 30 个关卡，采用 9:16 竖屏布局。

[在线体验](https://junlinr-cell.github.io/TripleMaze/)

## 玩法

点击箭头，若箭头前方没有遮挡，它就会沿自身路径滑出棋盘，进入下方的七格收集槽。同色任意三枚箭头自动消除；棋盘和收集槽全部清空即可过关，收集槽填满且无法消除则失败。

玩家需要同时考虑两件事：先移走哪些箭头能解除遮挡，以及怎样安排颜色顺序来节省槽位。被挡箭头无法移出，误点不扣生命，没有计时压力。支持撤回、重试和继续下一关；密集区域可通过缩放和拖动查看。

## 开发总结

### 实现思路与开发过程

我通过与 AI 持续沟通推进开发：先明确“箭头移出 + 七格收集 + 同色三消”的核心循环，再把规则、页面流程、关卡工具和操作反馈拆分为具体任务，由 AI 辅助编写代码、排查问题，我负责确定设计方向、体验验收并提出修改意见。

开发先围绕最小可玩闭环，完成遮挡判定、箭头移出、三消、胜负和首页到结果页的流程；随后逐步完善撤回、进度保存、竖屏适配和交互反馈。关卡设计进一步引入图片轮廓与配色，结合关卡编辑器、图片生成工具和求解校验，整理出当前的 30 关内容。

打磨阶段重点调整箭头圆角、点击回弹、沿线滑出、入槽曲线、三消聚合、粒子和音效，让每次操作都有清楚的反馈。每轮通过“提出体验问题、与 AI 讨论方案、实现修改、人工体验”的方式迭代。

### 遇到的问题与解决方案

- **遮挡和颜色选择叠加，容易产生混乱。** 将网格占用、前方遮挡和收集槽规则集中在独立逻辑层，先结算三消再判断槽满，保证规则一致。
- **图片关卡需要兼顾轮廓表现和可解性。** 用工具处理轮廓与主色，结合颜色数量校验、遮挡分析和有界求解辅助筛选；搜索预算耗尽与无解分别处理。
- **密集箭头在手机上不易辨认、点击。** 采用固定竖屏比例，加入缩放、拖动、圆角与按压反馈，并调整动画节奏。
- **Unity 压缩导出不能直接依赖静态托管的响应头。** 部署时自动解压 Brotli 构建文件并替换资源引用，生成适合 GitHub Pages 的静态文件。

### 收获与后续方向

AI 提高了代码实现和工具搭建的效率，而规则取舍、关卡节奏与操作体验仍需要持续提出明确问题并人工验收。后续重点是手机真机兼容、首屏加载速度，以及前几关的引导和难度曲线。

## 工程与部署

- `Assets/`、`Packages/`、`ProjectSettings/`：Unity 工程。使用 Unity 2022.3.62f3 打开，场景为 `Assets/Scenes/TripleMaze.unity`。
- `TripleMaze_WebGL/`：WebGL 导出文件。
- `Assets/TripleMaze/Editor/`：关卡编辑与图片生成工具，可从 Unity 的 `TripleMaze` 菜单打开。
- `Docs/`：实现说明、关卡生成资料、资源来源和迭代记录。部分记录对应早期版本，以当前工程和本 README 为准。
- `.github/workflows/pages.yml`：推送 `main` 后自动发布 WebGL。只发布网页构建，工程文件不进入站点。

本地可运行 `node scripts/prepare-pages.mjs` 生成 `_site/`，再通过 HTTP 静态服务器访问。请勿直接双击 HTML 运行 Unity WebGL。

本次整理检查网页文件与部署资源；手机浏览器上的具体游戏效果仍需人工验收。
